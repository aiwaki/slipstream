| 2026-08-03 | A complete regional-denial page is not a transport failure, and branded browsers cannot be assumed to have the unpublished companion. After an eligible unknown host establishes its exact public `system/plain` route, the daemon may start a background certificate-validating `GET /` against that same IP. The request carries no cookie, path, query, browser storage, or external asset and asks for identity encoding plus a bounded range. It is limited to `128 KiB`, two concurrent probes, eight new exact hosts per minute, and one probe per exact host per ten minutes. Only a syntactically complete HTTP response below `500` other than `429`, whose decoded identity-representation body contains a strong generic regional-denial marker, may request the existing independent owned-Geph semantic confirmation. HTTP chunk framing is removed before matching, so a marker split across chunks is handled without accepting compressed, incomplete, or capped data. A normal, incomplete, malformed, compressed, capped, rate-limited, unowned-backend, non-public-IP, static-policy, Discord, YouTube, Googlevideo, or network-wide-failure case remains inert. The active client stream is never delayed, replayed, closed, or rerouted; a proven exact-host route can affect only later requests. | 2026-08-02 | A generic unknown host that completed the mandatory local evidence ladder may use verified owned Geph once for the current replay-safe request, but opaque TLS payload cannot create or refresh a learned route. Independent confirmation is scheduled when the first owned-Geph payload arrives so a long-lived relay cannot outlive the candidate window; any session-draining replacement remains blocked until active sessions finish. A failed early worker retains exactly one post-drain retry, consumed when the active-session count reaches zero without permitting another retry loop. A live confirmation owns a unique worker token and cannot be expired by elapsed time; its exact token alone may release the host state, while thread-start failure releases that token and its probe cooldown immediately. A post-drain retry reserves the idle Geph drain before consuming its marker, so no new route can race between the zero-session observation and confirmation. The marker captures authorization while the original candidate is live and remains authoritative past candidate expiry until that single reserved retry is consumed. The early worker takes it before releasing its lifecycle session or attempting recovery, so the idle hook cannot launch a concurrent post-drain worker for the same host, and restores it only when an active session blocks the drain; it remains pending while owned Geph is unavailable, is restored after post-drain worker-start failure, and is retried by the monitor after backend recovery. Confirmation must reject unsuccessful or incomplete HTTP including `429 local_rate_limited` and require two consecutive complete, usable responses on distinct owned SOCKS sessions under one lifecycle reservation pinned to one exact owned listener PID. Ownership and PID equality are checked before and after each response and again at route commit; KeepAlive or external PID drift rejects the proof. A recovery worker reuses its held drain through proof and commit. If either response fails, route learning remains closed and only the existing session-drained, ownership-verified, at-most-two Geph replacement sequence may retry the same two-response proof under its global incident cooldown. Backend hold clears only after stable proof. Each semantic probe shares one bounded monotonic deadline across SOCKS, TLS and HTTP reads.
